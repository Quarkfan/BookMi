# 面向 2000+ 实体藏书的 iOS 书房管理 App PRD

版本：v1.0  
定位：自用、本地优先、无自有服务端、iCloud 备份/同步、可配置大模型 API

---

## 1. 背景

当前已有一个类似的藏书管理 App，但维护情况不理想。为了避免数据被旧工具锁定，需要开发一款自用 iOS App，用于长期管理个人 2000+ 实体藏书。

本 App 不面向大众商店化运营，不建设自有服务端，不提供账号体系。核心目标是让个人藏书数据长期可维护、可搜索、可批量整理、可导入导出、可通过 iCloud 备份和恢复。

---

## 2. 产品定位

一款面向个人长期使用的本地优先型书房管理 App，支持扫码、CSV 导入、网络搜索、手动录入、拍照识别出版信息、书柜位置管理、标签管理、阅读进度、借出管理、统计分析、导入导出、iCloud 备份/同步和本地数据维护。

---

## 3. 产品原则

### 3.1 无自有服务端

App 不建设自有服务端。

明确不包含：

| 项目 | 是否支持 | 说明 |
|---|---:|---|
| 自建用户系统 | 否 | 不做注册、登录、账号管理 |
| 自建后端 API | 否 | 不维护业务服务端 |
| 自建数据库服务 | 否 | 核心数据保存在本地或 iCloud |
| 自建文件存储 | 否 | 封面、备份文件使用本地与 iCloud |
| 自建同步服务 | 否 | 备份与同步依赖 Apple iCloud |
| 自建 OCR 服务 | 否 | 使用用户配置的大模型 API |

### 3.2 本地优先

所有核心数据优先保存在本地。离线状态下仍然支持：

- 查看已有图书。
- 搜索已有图书。
- 编辑图书。
- 修改书柜。
- 修改标签。
- 修改阅读状态。
- 修改借出状态。
- 导入本地 CSV。
- 导出本地数据。
- 创建本地备份。

网络仅用于：

- 查询网络图书信息。
- 匹配封面。
- 调用用户配置的大模型 API。
- iCloud 备份与同步。

### 3.3 数据可控

App 必须保证用户可以完整拿回自己的数据。

必须支持：

- CSV 导入。
- CSV 导出。
- JSON 导出。
- 封面 ZIP 导出。
- 完整备份包导出。
- 完整备份包恢复。
- 备份包保存到 iCloud。
- 从 iCloud 备份恢复。
- 可选导出字段。
- 稳定的图书 UUID。
- 不以 ISBN 作为主键。

### 3.4 面向 2000+ 图书规模

产品设计必须默认用户已有 2000+ 实体藏书。

重点能力：

- 高效搜索。
- 拼音索引。
- 模糊搜索。
- 书柜/位置管理。
- 批量操作。
- CSV 迁移。
- 重复检测。
- 封面批量处理。
- 数据质量检查。
- 完整备份恢复。

### 3.5 一次性完整交付

本 PRD 不按阶段拆分。所有需求均作为完整目标范围设计。开发实现可以按内部任务排期推进，但产品范围不拆成 MVP、二期或三期。

## 4. 目标用户

主要用户为 App 作者本人，用于管理个人实体藏书。

特征：

- 当前已有 2000+ 本图书。
- 有从旧 App 或旧数据源迁移的需求。
- 更关注长期可维护，而不是上架商店。
- 能接受偏工程化的高级配置。
- 需要配置自己的大模型 API Endpoint 和 API Key。
- 需要 iCloud 作为备份与同步手段。

## 5. 核心使用场景

### 5.1 从旧 App 迁移 2000+ 图书

用户从旧 App 导出 CSV 和封面文件，在新 App 中执行迁移导入。App 支持字段映射、封面匹配、重复检测、导入预览和导入报告。

### 5.2 扫码快速入库

用户设置默认书柜和默认标签，连续扫描图书 ISBN 一维码。App 自动查询图书信息、匹配封面，并将图书加入默认书柜和标签。

### 5.3 拍照识别出版信息

用户拍摄图书版权页或封面，App 调用用户配置的大模型 API，返回结构化图书信息。用户确认或修正后保存。

### 5.4 查找一本书的位置

用户输入书名、作者、拼音、首字母、ISBN、标签或书柜关键字，App 本地搜索并展示图书所在书柜和详细位置。

### 5.5 批量整理图书

用户在搜索结果、书柜详情或标签详情中批量选择图书，执行批量移动书柜、批量添加标签、批量删除、批量标记读完等操作。

### 5.6 借出一本书

用户进入图书详情页，记录借阅人、借出时间、预计归还时间和备注。归还后保留历史借出记录。

### 5.7 数据备份与恢复

用户创建完整备份包，保存到本地或 iCloud。需要恢复时，可从本地或 iCloud 备份中选择覆盖恢复、合并恢复或仅导入图书。

## 8. 图书录入

### 8.1 ISBN 扫码录入

用户通过摄像头扫描图书背面的一维码 ISBN。

功能要求：

1. 支持 ISBN-10 和 ISBN-13。
2. 自动识别一维码。
3. 根据 ISBN 查询网络图书信息。
4. 自动填充书名、作者、出版社、出版时间、封面、简介等字段。
5. 支持保存前编辑。
6. 支持连续扫码。
7. 支持默认书柜。
8. 支持默认标签。
9. 支持默认购买渠道，可选。
10. 支持查询失败后转手动录入。

验收标准：

| 编号 | 标准 |
|---|---|
| SCAN-01 | 扫描合法 ISBN 后可以识别 ISBN 字符串 |
| SCAN-02 | 有网络时可以尝试查询图书信息 |
| SCAN-03 | 查询成功后自动填充图书字段 |
| SCAN-04 | 查询失败时允许手动录入 |
| SCAN-05 | 设置默认书柜后，新录入图书自动绑定该书柜 |
| SCAN-06 | 设置默认标签后，新录入图书自动附加标签 |
| SCAN-07 | 连续扫码时，保存一本后可以继续扫描下一本 |

### 8.2 网络搜索录入

用户通过关键词搜索图书并加入藏书。

支持关键词：

- 书名。
- 作者。
- ISBN。
- 出版社。

验收标准：

| 编号 | 标准 |
|---|---|
| SEARCH-ADD-01 | 用户输入关键词后可以返回候选图书 |
| SEARCH-ADD-02 | 用户可以查看候选图书详情 |
| SEARCH-ADD-03 | 用户可以选择候选图书加入藏书 |
| SEARCH-ADD-04 | 加入前可以编辑图书信息 |

| 出版时间 | 否 | 可为空 |

| 版次 | 否 | 可为空 |

### 8.4 拍照识别出版信息

用户拍摄图书版权页或封面，App 调用用户配置的大模型 API 进行识别。

识别目标字段：

- 书名。
- 副标题。
- 作者。
- 译者。
- ISBN。
- 出版社。
- 出版时间。
- 版次。
- 印次。
- 页数。
- 定价。
- 丛书。
- 分类。
- 原始文本。
- 置信度。

流程：

```text
拍照
↓
压缩图片
↓
调用用户配置的大模型 API
↓
解析结构化 JSON
↓
展示确认页
↓
用户确认或修改
↓
保存图书
```

验收标准：

| 编号 | 标准 |
|---|---|
| OCR-01 | 用户可以拍摄版权页或封面 |
| OCR-02 | App 可以调用配置的大模型接口 |
| OCR-03 | 模型返回后可以解析结构化结果 |
| OCR-04 | 识别结果必须进入确认页，不能静默入库 |
| OCR-05 | 用户可以编辑识别字段 |
| OCR-06 | 保存后图书进入本地数据库 |

### 8.5 CSV 导入

CSV 导入是核心迁移能力。

功能要求：

1. 支持选择本地 CSV 文件。
2. 支持编码识别或选择。
3. 支持字段映射。
4. 支持预览导入结果。
5. 支持重复检测。
6. 支持失败行提示。
7. 支持标签拆分。
8. 支持作者拆分。
9. 支持导入时创建缺失书柜。
10. 支持导入时创建缺失标签。
11. 支持导入时设置默认书柜、默认标签、默认购买渠道。
12. 支持导入时匹配封面目录或封面 ZIP。
13. 支持导入报告。
14. 支持反复导入。
15. 支持仅更新空字段、覆盖已有字段、跳过已有图书。

重复判断规则：

| 优先级 | 规则 |
|---:|---|
| 1 | legacyId 相同，视为同一条迁移记录 |
| 2 | ISBN 相同，视为可能重复 |
| 3 | ISBN 为空时，书名 + 作者相同，视为可能重复 |
| 4 | 用户可选择跳过、覆盖、合并或作为新书导入 |

导入报告：

| 指标 | 说明 |
|---|---|
| 总行数 | CSV 总记录数 |
| 成功新增 | 新增图书数量 |
| 更新已有 | 更新已有图书数量 |
| 跳过重复 | 重复但未处理数量 |
| 失败数量 | 解析失败或保存失败数量 |
| 缺失 ISBN | 数据质量指标 |
| 缺失封面 | 数据质量指标 |
| 缺失书柜 | 数据质量指标 |
| 创建标签数 | 自动创建标签数量 |
| 创建书柜数 | 自动创建书柜数量 |

## 9. AI / OCR 设置

路径：

```text
设置 → AI / OCR 设置
```

配置项：

| 配置项 | 类型 | 必填 | 说明 |
|---|---|---:|---|
| 启用 AI/OCR | Switch | 是 | 是否启用大模型识别 |
| API Base URL | TextField | 是 | 用户配置调用地址 |
| API Key | SecureField | 是 | 用户配置密钥 |
| Model Name | TextField | 否 | 模型名称 |
| 请求格式 | Picker | 是 | OpenAI-Compatible / Custom |
| Timeout | Number | 否 | 默认 60 秒 |
| Temperature | Number | 否 | 默认 0 |
| Max Tokens | Number | 否 | 可配置 |
| 识别语言 | Picker | 否 | 自动 / 中文 / 英文 |
| 保存原始响应 | Switch | 否 | 便于排查 |
| 测试连接 | Button | 是 | 验证配置可用性 |

安全要求：

1. API Key 保存到 iOS Keychain。
2. API Key 默认不写入普通配置文件。
3. API Key 默认不包含在备份包中。
4. 如果用户选择导出包含 API Key 的配置，必须提示敏感风险。
5. 启动密码不能替代 Keychain。

| 字段 | 说明 |
|---|---|

| 备注 | 可选 |
| 排序 | 可选 |
| 图书数量 | 系统统计 |
| 创建时间 | 系统生成 |
| 更新时间 | 系统生成 |

## 24. 非功能需求

### 24.1 性能

| 场景 | 要求 |
|---|---|
| 2000 本图书 | 搜索结果 300ms 内返回 |
| 10000 本图书 | 搜索结果 1s 内返回 |

| 索引重建 | 支持后台执行并显示进度 |

### 24.2 稳定性

- 导入失败不能破坏已有数据。
- 备份失败要提示明确原因。
- 恢复前必须创建当前数据备份或提示用户。
- 批量操作应可确认，避免误操作。
- 关键操作应有日志。

### 24.3 可维护性

- 数据库 schema 需要版本号。
- 备份包需要 backupVersion。
- JSON 导出需要 schemaVersion。
- 数据模型应尽量稳定。
- 导入导出应避免绑定单一外部服务格式。
