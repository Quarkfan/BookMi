## 问题 2: 扫码录入闪退 🟡

### 当前状态
扫码页面打开即闪退（不是扫码后，是点击"扫码录入"按钮瞬间）。

### 已尝试的修复
1. **移除 `@MainActor`** — 避免 actor 隔离冲突
2. **条件渲染** — `CameraPreviewView` 只在 `isScanning == true` 时创建
3. **主线程保障** — `startScanning` → `doSetupSession` → `setupSession` 全部确保在 main thread 执行
4. **详细日志** — 每个关键步骤都加了 `print("[Scanner] ...")` 日志
5. **错误捕获** — `startRunning()` 用 `try/catch` 包裹

### 当前代码流（ScannerView.swift）
```
ScannerView body:
  ├── if viewModel.isScanning → CameraPreviewView(session:)
  ├── else → Color.black
  └── .onAppear → viewModel.startScanning()

startScanning():
  ├── DispatchQueue.main.async → doSetupSession()

doSetupSession():
  ├── case .authorized → setupSession() (同步，已在 main)
  ├── case .notDetermined → requestAccess → main.async → setupSession()
  └── case .denied → error = "相机权限被拒绝"

setupSession():
  ├── session.beginConfiguration()
  ├── 添加 input (back camera)
  ├── 添加 output (metadata)
  ├── session.commitConfiguration()
  └── try session.startRunning() → setupComplete = true, isScanning = true

stopScanning():
  └── main.sync { session.stopRunning() } if not on main thread
```

### 可能需要排查的方向
1. **`nonisolated metadataOutput` 中的主线程调用** — `UINotificationFeedbackGenerator().notificationOccurred(.success)` 需要在主线程，但有 Swift 6 警告
2. **View 生命周期** — sheet 呈现时 `onAppear` 和 view body 的时序
3. **Info.plist 权限描述** — 确认 `NSCameraUsageDescription` 已配置
4. **真机日志** — 需要在 Xcode console 中看 `[Scanner]` 日志，确定崩溃发生在哪一步

### 下一步
- 让用户在 Xcode 中运行，提供 console 日志
- 如果 `startRunning()` 抛异常，需要看具体 error message
- 如果是 EXC_BAD_ACCESS，可能是 `CameraPreviewView` 的 layer 问题

## 问题 3: CSV 导入报错 🟡

### 原因
GRDB 7.x 使用 snake_case 数据库列（`authors_json`），但 Swift 属性是 camelCase（`authorsJSON`）。之前添加了错误的 `databaseColumnMapping` API（不存在于 GRDB 7.x）。

### 已修复
**文件**: `BookRoom/Core/Database/Models/Book.swift`
```swift
// 修复前（错误）
static var databaseColumnMapping: DatabaseColumnMapping { ... }

// 修复后（正确）
static var databaseColumnEncodingStrategy: DatabaseColumnEncodingStrategy {
    .convertToSnakeCase
}
```

### 已加错误日志
**文件**: `BookRoom/Core/Database/CSVService.swift`
- INSERT 失败时打印 book title、ISBN、authors JSON
- 方便在 Xcode console 中看到具体是哪条数据、哪个字段出了问题

### 下一步
- 用户确认 file picker 已正常工作（✅ 用户反馈"可以选文件了"）
- 但导入仍然报 SQLite 错误 — 需要看 Xcode console 中的 `[CSVImport]` 日志
- `databaseColumnEncodingStrategy` 只对**写入**（INSERT/UPDATE）生效，对**读取**可能还需要确认 `databaseDecodingUserInfo` 配置

## 问题 4: 网络搜索不出结果 + UI 丑 🟡

### 已修改的文件

**BookLookupService.swift**:
1. 添加 `URLSession.bookLookup` 专用配置：`timeoutIntervalForRequest = 15s`
2. 所有 provider 改用 `URLSession.bookLookup` 替代 `URLSession.shared`
3. `search()` 返回 `SearchResult` 枚举：`.success`, `.error(String)`, `.notFound`
4. Open Library search 改用 `q=` 替代 `title=`（搜索结果更全）
5. Google Books search 加了 `langRestrict=zh` 和 `intitle:`/`inauthor:` 查询
6. 所有关键步骤加了 `print("[BookLookup]...")` 日志

**AddBookView.swift** (BookSearchSheet):
1. 重新设计了搜索 UI：
   - 初始状态：地球图标 + 提示
   - 搜索中：ProgressView + "正在搜索网络图书..."
   - 搜索失败：wifi.slash 图标 + 错误信息 + 重试按钮
   - 未找到：放大镜图标 + "尝试更换搜索关键词"
   - 有结果：显示结果数量 + 列表
2. 搜索按钮改为图标按钮（magnifyingglass）
3. 背景色改为 `.systemGroupedBackground`

### 潜在问题

- 如果两个 API 都超时，用户会看到 error 信息
- 可能需要考虑添加国内 API（如豆瓣，但需要 key）

### 下一步

## 重要注意事项

1. **GRDB 7.10.0** — 正确的 snake_case 配置是 `databaseColumnEncodingStrategy: .convertToSnakeCase`
2. **AVCaptureSession** — `startRunning()` 必须在 main thread 调用，同步执行
3. **URLSession** — 默认无超时，必须用自定义 configuration
4. **fileImporter** — 返回 security-scoped URL，需要 `startAccessingSecurityScopedResource()` + 复制到 app 沙盒
5. **Scanner 崩溃** — 需要 Xcode console 中的 `[Scanner]` 日志来定位崩溃点
